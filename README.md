## 💻 プロジェクト概要

[プロジェクト概要を記載]
C# コンソールアプリ+SQLiteを使用した家計簿アプリです。

支出データをローカルの SQLite に保存し、  
「支出の追加」「支出内容を変更」「支出の削除」「支出一覧の表示」といった  
家計簿として必要な基本操作を行うことができます。

「まずは小さく動くものを作る」をテーマに、
後から機能を拡張しやすい構造を意識して開発しています。
入力処理・DB処理・表示処理をクラスごとに分離し、責務を明確にすることで、
機能追加や修正がしやすい設計になっています。

## 📐 システム設計

[クラス設計など、設計について説明を記載]
### クラス設計
- `Program` クラス  
  - メインメニューの表示 
  - ユーザー入力に応じて各機能を呼び出す

- `Expense` クラス  
  - 支出データの追加/編集/削除/表示の各処理を担当
  - 入力チェックやキャンセル処理もここで実施

- `ExpenseRepository` クラス
  - SQLiteへのCreate/Read/Update/Delete処理を担当
  - データの取得・保存・更新・削除

- `Expense` クラス
  - 支出データ1件分を表すモデルクラス

#### 実装機能
#### 支出の追加  
- 日付  
- 金額  
- カテゴリ  
- メモ  
→ 入力内容を SQLite に保存
- ユーザーが入力した日付・金額・カテゴリ・メモを検証し、SQLite に保存します。
- 入力値が不正な場合は再入力を促し、cancel と入力された場合は処理を中断します。

#### 支出の編集  
1. 一覧を表示  
2. 編集したい項目を選択  
3. 値を入力  
4. SQLite の該当レコードを更新
- 一覧表示 → 編集対象の選択 → 新しい値の入力 → DB更新
  という流れで、必要な項目だけを柔軟に変更できます。

#### ● 支出の削除  
1. 一覧を表示  
2. 削除したい項目を選択  
3. 削除確認  
4. SQLite のレコードを削除
一覧表示 → 削除対象の選択 → 削除確認（yes/no）
という安全なフローで誤操作を防ぎます。

## 💡 工夫した点・技術的アピール

[開発において意識した点、工夫した点などアピールポイントを記載]
- **小さく作って拡張しやすい構造**  
  最初は必要最低限の機能だけを実装し、  
  後から機能を追加しやすいようにコードを分割・整理しています。

- 入力チェックの共通化
  - cancel 判定
  - 数値チェック
  - 空文字チェック
これらをメソッド化し、重複コードを削減。
ユーザー操作の流れが自然になるように設計しています。

- **SQLite を使った軽量なデータ管理**  
  外部サーバーを必要とせず、ローカルで完結するため、  
  環境構築が簡単で扱いやすい。

- **読みやすさを意識したコード**  
  初めて読む人でも理解しやすいよう、  
  メソッド名・変数名・コメントを丁寧に記述しています。

- **ブランチ運用の工夫**  
  `feature/add-kakeibo-app`ブランチで開発。    
  mainブランチを安全に保ち、作業内容を一つのブランチにまとめています。
　プルリクエストでレビューを受けながら進める開発スタイルを採用しています。

## 🔮 今後の展望

今後は、家計簿アプリとしての実用性を高めるため、
以下のような機能追加を検討しています。

- 月ごとの集計機能  
  月単位で支出を集計し、合計額やカテゴリ別の割合を表示できるようにする。

- カテゴリ別の統計表示  
  食費・交通費など、カテゴリごとの支出傾向を可視化する。

- 検索機能の追加  
  日付範囲やカテゴリで絞り込みができるようにし、
  過去の支出を探しやすくする。

- GUI 化（WPF / MAUI など）  
  コンソールアプリから GUI アプリへ発展させ、
  より直感的に操作できる家計簿アプリへ進化させたい。

- 収入管理の追加  
  支出だけでなく収入も記録し、
  月ごとの収支バランスを確認できるようにする。
